# 움직이는 쓰레기통 (자율주행 캐치 로봇)

낙하하는 쓰레기를 카메라로 인식하고, 궤적을 예측해 로봇이 물체 아래로 이동하여 받아내는
3륜 홀로노믹 자율주행 로봇.

## 어떻게 동작하나

사진 한 장은 깊이를 담지 못한다 — 작은 물체가 가까이 있는 것과 큰 물체가 멀리 있는 것이
똑같은 픽셀을 만들기 때문이다. 이 시스템은 **중력을 자로 써서** 그 모호성을 깬다.
"이 궤적이 9.8 m/s²의 중력으로 만들어지려면 거리가 얼마여야 하는가"를 역으로 풀면
스케일이 확정된다. **물체 크기를 전혀 몰라도 되고**, bbox 중심만 쓰므로 물체가 공중에서
회전해도 무관하다.

```
                     ┌─────────── 파이5 (Python, 60 Hz) ───────────┐
  [카메라] ─프레임──▶ │ vision      YOLO → bbox 중심 + 왜곡 보정     │
                     │    ↓                                        │
                     │ trajectory  중력 제약 최소제곱 → 3D 궤적      │
                     │    ↓        (매 프레임 관측 누적 + 재피팅)     │
                     │ trajectory  착지점 · 남은시간 예측            │
                     │    ↓                                        │
                     │ control     남은거리 ÷ 남은시간 = 목표 속도   │
                     └──────────────────┬──────────────────────────┘
                                        │ USB CDC
                       속도명령 ▼       ▲ 오도메트리
                     ┌──────────────────┴──────────────────────────┐
                     │            피코 (C, 1 kHz)                   │
                     │  엔코더(PIO) → 순기구학 → 칼만 → 오도메트리   │
                     │  목표속도 → 역기구학 → PID → PWM             │
                     └──────────────────┬──────────────────────────┘
                                        ▼
                                  [모터 ×3 / 옴니휠 ×3]
```

**역할 분담:** 파이5는 "어디로 얼마나 빨리 가야 하는가"를 결정하고, 피코는 "그 속도를
정확히 내는 것"만 한다. **피코는 궤적도 착지점도 모른다.**

  + 번들 **M12 어안** ZH3019-14 (표기 2.8 mm F2.2 D148°)
    실측: **대각 133.5° / 수평 94.0°**, f_px 973 (2026-08-19 캘리브레이션)
- 모터 내장 엔코더 3개 (홀센서 A/B 2상, 16 CPR, **VCC는 반드시 3.3 V**)

### 구동부

- FIT0493 12V DC 기어드모터 3개 (350RPM, 34:1 기어비)
- BTS7960 모터드라이버 3개
- NEXUS 14049 100 mm 옴니휠 3개 (고무 롤러), 120° 삼각 배치

### 전원 (2계통 분리, 접지는 공통)

- 두뇌용: 18650 UPS 5 V → 파이5 / AI HAT / 카메라 / 피코
- 모터용: 3S LiPo 11.1 V → PDB → 모터드라이버 3개

## 목표 스펙

| 항목 | 값 |
|---|---|
| 투척 높이 | 2.0 m |
| 유효 캐치 반경 | **40 cm (보증)** / 48 cm (μ=0.5 계산) |
| 통 입구 지름 | **30 cm** (깊이 20~25 cm) |
| 인식 주기 / 제어 주기 | 60 fps / 1 kHz |
| 검출 모델 | YOLOv8n 단일 클래스 `trash` (커스텀 학습 → Hailo `.hef`) |

**유효 캐치 반경 = 로봇 이동거리(33 cm) + 통 입구 반경(15 cm)** 이다. 물체는 로봇 중심이
아니라 통 안에만 들어오면 되기 때문이다.

> 병목은 모터가 아니라 **바닥 마찰**이다. 모터는 16.3 m/s²를 낼 수 있는데 마찰 한계가
> 2.45 m/s²다. `a = 0.5μg`에 질량이 없다는 것은 **통을 크게 만드는 비용이 사실상 0**이라는
> 뜻이기도 하다 ([physics.md 2장](docs/physics.md#2-3륜-옴니의-힘-분배)).

**비목표:** 여러 물체 동시 추적, 장애물 회피, 로봇 회전(θ) 제어, 캐치 성공/실패 자동 판정,
통 비우기.

## 개발 언어

| 보드 | 언어 | 선정 이유 |
|---|---|---|
| 라즈베리파이 5 | Python | Hailo NPU 공식 SDK가 Python API 우선 지원. OpenCV/NumPy 생태계. 무거운 연산은 NPU가 처리하므로 Python 오버헤드가 병목이 아니다 |
| 라즈베리파이 피코 | C (Pico SDK) | PIO 엔코더 타이밍 정밀도, PID 루프 지터 최소화 |

## 현재 상태

**하드웨어 조립 전 — 로직은 완성, 실측값과 연동이 남았다.**

궤적 추정은 합성 투척으로 검증 완료(착지 오차 중앙값 0.1~0.4 cm)했으나,
그 검증이 **확정 렌즈와 다른 조건에서 돌아간 점**은 재확인이 필요하다.

막혀 있는 지점과 우선순위는 [`architecture.md` 5장](architecture.md#5-지금-막혀-있는-지점).
