# pi5 남은 작업

> 2026-08-19 갱신. 렌즈가 6mm 핀홀이 아니라 **M12 어안**으로 확정되고, 실측 캘리브레이션이
> 끝나면서 1번 항목 대부분이 채워졌다. 모터도 바뀌었다(FIT0493 → FIT0186). 알고리즘 설명은
> [`../algorithm.md`](../algorithm.md) — 단, 4장 성능표는 아직 옛 렌즈 스펙 기준이라 갱신 필요.

## 1. 실측해서 값만 채우면 되는 것 (config.py)

- [x] **렌즈 확인** ★ — **번들 M12 어안 (ZH3019-14, 표기 2.8mm F2.2)로 확정.**
      **표기 화각(D=148°/H=118°)은 과장이었다** — 저가 M12 렌즈에서 흔한 일이다.
      **실측 대각 화각은 108.8°** (수평 89.3° / 수직 66.9°), 실효 초점거리 3.36mm.
      줄자 검증(벽 1.02m 거리)으로 캘리브레이션 예측과 8% 이내로 교차확인 완료 —
      표기 사양으로 역산했던 옛 값(755px/138°)은 실측과 74cm(25%) 벗어나 폐기.
      **`cv2.fisheye`가 쓰는 등거리 모델과 일치** (화면 안 입사각 범위에서 θ_d/θ = 0.96~0.99).

- [x] **`CAMERA_FX/FY/CX/CY`** — 체스보드 캘리브레이션 완료 (`prep/calibrate.py`,
      23장, RMS 재투영오차 0.411px, 9칸 화면분할 커버 + 기울임 포함).
      `CAMERA_FX=973.0, CAMERA_FY=974.0, CAMERA_CX=657.0, CAMERA_CY=535.0`.
      독립적인 2차 검증(격자판 실측, 카메라 앞 1m에 중심기준 좌우/상하 50cm + 10cm
      단위 격자)으로도 f_px 920~993 나와서 서로 확인됐다.
      cx가 화면 중앙(728)에서 71px 왼쪽 — **센서가 광축에 정확히 안 맞춰져 있다**
      (M12 특성상 흔함, 문제 아님, 캘리브레이션이 알아서 보정해줌).

      ⚠ **초점을 다시 맞추면 이 값 전부 무효.** M12는 나사로 돌려 초점을 잡는 구조라
      실효 초점거리가 같이 바뀐다. 렌즈를 건드렸으면 재캘리브레이션할 것.

- [x] **`CAMERA_DISTORTION`** — 캘리브레이션에서 같이 나옴. **어안이므로 (k1,k2,k3,k4) 4개**
      (핀홀의 (k1,k2,p1,p2,k3) 5개와 다르니 섞지 말 것).
      현재값 `(-0.1432, 0.0282, -0.0445, 0.028898)`.

      ⚠⚠ **k4 확인 필요** — inseon 캘리브레이션 원본은 k4=0.288이었는데, k1~k3는 별도
      재촬영본(같은 세션, 다른 사람)과 거의 일치하면서 k4만 정확히 10배 차이난다 —
      소수점 오타로 의심됨. 확인 전까지 재촬영본 값(0.028898)을 대신 쓰는 중.
      실측 CSV(던지기 1개, 최대 입사각 54°대)로 교차검증한 결과 이 범위에서는
      두 값 차이가 착지 예측에 3mm~1.5cm밖에 안 벌어져 급하지 않음 — **팀 확인만 하면 됨.**

      화면 밖(70°+)에서는 왜곡 다항식이 발산한다(θ_d/θ가 2.13까지 튐). 화면 최대
      입사각(54.4°, 모서리)보다 밖이라 실사용엔 문제없음.

- [ ] **`CAMERA_OFFSET_M` — 상수 자체가 없다** ★ (미해결, 이전과 동일)
      `trajectory.predict_landing`이 "카메라 = 로봇 회전 중심"을 전제하는데, 설계상
      카메라는 통 입구 림(중심에서 약 15cm)에 있다. 그대로 두면 매번 같은 방향으로
      15cm 어긋난다 — **통 반경(약 40cm)의 절반 가까이다.** 장착 위치 확정 후 상수를
      넣고 착지점에서 빼면 된다 (ω=0이라 단순 벡터 덧셈).

- [ ] `YOLO_MODEL_PATH` — **PC 검증용 `.pt`는 학습 완료**, 실제 영상+YOLO로 궤적 예측까지
      테스트해봄 (`predict_trajectory.py`/`yolo_to_csv.py`, 아래 3번 참고). **Hailo용
      `.hef` 변환은 아직 미착수** — ONNX 내보내기 + Dataflow Compiler(x86 Linux 필요)
      단계가 남아있다.
- [ ] **`YOLO_IMGSZ`** — 학습에 실제로 쓴 값과 맞출 것. `train_yolo.py`가 끝날 때
      출력한다. 다르면 변환도 되고 추론도 되는데 **정확도만 조용히 떨어지고**,
      이 시스템에서 정확도 저하는 곧 bbox 중심 노이즈 = 깊이 추정 악화다
- [ ] `ROBOT_MAX_SPEED_MPS` — **모터가 바뀌면서 이론값도 갱신됨** (FIT0493 350RPM →
      **FIT0186 251RPM, 기어비 43.8:1**). 부하 감쇠 포함 이론값 **1.22 m/s**
      (기존 1.8에서 하향). 3륜 옴니는 방향에 따라 바퀴 하나가 먼저 포화하므로 이 값을
      **모든 방향 보장 하한**으로 쓴다. **여전히 실측 필요** — 모터 도착 후 PWM 100%
      직진시키고 엔코더 속도가 평평해지는 값으로 갱신. `pico/config.h`의
      `MAX_BODY_SPEED_MPS`와 반드시 같은 값이어야 한다. 같이 잴 것: 가속 시간, 정지거리.
- [x] `SERIAL_PORT` — `communication.SerialLink`가 pyserial로 포트 여는 코드 완료,
      `port` 인자로 오버라이드 가능. 장치 경로 자체(`/dev/ttyACM0` 등)는 실제 연결 후 확인.
