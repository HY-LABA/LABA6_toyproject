# pi5 남은 작업

> 2026-08-10 갱신. 깊이 추정 방식 전환으로 없어진 항목이 많다 (`algorithm.md` 참고).

## 1. 실측해서 값만 채우면 되는 것 (config.py)

- [x] **렌즈 초점거리 확인** ★ — **모듈 번들 M12 2.8mm F2.2, 대각 화각 140°로 확정.**
      (`prep/TROUBLESHOOTING.md`의 카메라 비교표도 처음부터 "IMX296 + M12 2.8mm"였다.
       config.py에 적혀 있던 "6mm CS 렌즈"가 잘못된 추정이었다.)

      **이 렌즈는 핀홀이 아니다.** 2.8mm를 핀홀로 넣으면 대각 96.5°가 나와 140°와
      안 맞는다. 등입체각 어안(`r = 2f·sin(θ/2)`)이 140°와 −17% TV 왜곡을 동시에 설명한다.
      → `CAMERA_MODEL = "fisheye"`, `CAMERA_FX = 792` (등입체각 역산)

      | 모델 | f_eff | f_px | 비고 |
      |---|---|---|---|
      | 등입체각 (사양 부합) | 2.733mm | **792** | 현재 값 |
      | 등거리 (cv2.fisheye) | 2.566mm | 744 | 캘리브레이션이 뱉을 값 |
      | 핀홀 | 1.141mm | 331 | 성립 안 함 |

      화각: 수평 109.4° / 수직 80.3° / 대각 140.0°

      **⚠ `algorithm.md` 4장 시뮬레이션을 다시 돌려야 한다** — 원래 기준이 "4mm 이하면
      화각-정확도 균형이 달라진다"였는데 2.8mm가 거기 해당한다.

- [ ] **`CAMERA_FX/FY/CX/CY`** — 체스보드 캘리브레이션으로 확정.
      **`prep/calibrate.py`가 준비돼 있다** (`capture` → `solve --model fisheye`).
      위 값은 사양 역산이지 실측이 아니다. M12는 나사로 초점을 맞추는 구조라 실효
      초점거리가 달라지고, 주점(cx,cy)도 화면 정중앙이 아니다.
      **f가 10% 틀리면 깊이도 10% 틀어진다.**

      cv2.fisheye는 **등거리** 모델이라 f_px가 744 근처로 나오는 게 정상이다.
      792에서 6% 낮다고 놀라지 말 것 — 같은 렌즈를 다른 모델로 기술한 것뿐이다.

      데이터 수집은 막지 않는다 (`capture_dataset.py`는 f를 쓰지 않는다).

- [ ] **`CAMERA_DISTORTION`** — 위 캘리브레이션에서 같이 나온다.
      **어안이므로 (k1,k2,k3,k4) 4개다** — 핀홀의 (k1,k2,p1,p2,k3) 5개와 개수도 의미도
      다르니 섞지 말 것.
      None인 동안은 `vision.py`가 `fisheye.py`의 해석적 등입체각 근사로 대신 편다
      (원본 좌표를 그대로 흘리면 안 된다 — 아래 참고).

      > **⚠ 이 오차는 재투영 잔차로 못 잡는다.** 어안 좌표를 보정 없이 넣으면 착지 예측이
      > 입사각 62°에서 10cm, 80°에서 **158cm** 틀리는데 **잔차는 1.9~2.7px로 계속
      > `MAX_RESIDUAL_PX`(4.0) 아래**다. 잔차는 관측끼리의 일관성을 재지 투영 모델의
      > 정확성을 재지 않기 때문이다. 캘리브레이션으로 직접 확인하는 수밖에 없다.
- [ ] **`CAMERA_OFFSET_M` — 상수 자체가 없다** ★
      `trajectory.predict_landing`이 "카메라 = 로봇 회전 중심"을 전제하는데, 설계상
      카메라는 통 입구 림(중심에서 약 15cm)에 있다. 그대로 두면 매번 같은 방향으로
      15cm 어긋난다 — **통 반경과 같은 크기다.**
      장착 위치를 확정한 뒤 상수를 넣고 착지점에서 빼면 된다 (ω=0이라 단순 벡터 덧셈).
      ../docs/open-questions.md 참고.

- [ ] `YOLO_MODEL_PATH` — 학습·Hailo 변환 완료 후 `.hef` 경로
- [ ] **`YOLO_IMGSZ`** — 학습에 실제로 쓴 값과 맞출 것. `train_yolo.py`가 끝날 때
      출력한다. 다르면 변환도 되고 추론도 되는데 **정확도만 조용히 떨어지고**,
      이 시스템에서 정확도 저하는 곧 bbox 중심 노이즈 = 깊이 추정 악화다
- [ ] `ROBOT_MAX_SPEED_MPS` — 모터 도착 후 PWM 100% 직진으로 실측.
      `pico/config.h`의 `MAX_BODY_SPEED_MPS`도 같은 값으로 맞출 것.
      **같이 잴 것: 가속 시간, 정지 거리(오버슈트 크기)**
- [ ] `SERIAL_PORT` — 피코 연결 후 장치 경로 (`/dev/ttyACM0` 등)

## 2. 값을 채워도 별도 연동 코드가 필요한 것

      `prep/camera.py`에 노출·게인·auto_lock·노이즈리덕션 처리가 이미 다 들어 있으므로

## 3. 만들어야 하는 것

- [x] **`prep/calibrate.py`** — 만들었다. `capture`(체스보드 촬영, 3x3 커버리지 추적) +
      `solve`(계산 → JSON + config 스니펫) 두 서브커맨드.
      **모델이 pinhole이 아니라 fisheye로 바뀌었다** — 프로파일의 `calib_model`을 보고
      `cv2.calibrateCamera` / `cv2.fisheye.calibrate`를 자동으로 고른다.
      실측 f_px에서 **렌즈 mm를 역산해 출력**하므로 렌즈 각인을 못 읽어도 확정된다.
      체스보드 인쇄해서 15~20장 찍고 `solve --model fisheye` 하면 된다.
      **데이터 수집을 막지 않는다** — `capture_dataset.py`는 초점거리를 쓰지 않는다
