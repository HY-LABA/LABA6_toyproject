> 채워야 할 값과 연동해야 할 코드 목록. 알고리즘 설명은 [`../algorithm.md`](../algorithm.md).

## 1. 실측해서 값만 채우면 되는 것 (config.py)

- [x] **렌즈 확인** ★ — **번들 M12 어안 ZH3019-14 (공칭 2.8mm, F2.2)로 확정.**
      (`prep/TROUBLESHOOTING.md`의 카메라 비교표도 처음부터 "IMX296 + M12 2.8mm"였다.
       config.py에 적혀 있던 "6mm CS 렌즈"가 잘못된 추정이었다.)

      **이 렌즈는 핀홀이 아니라 어안이다** (실측 대각 108.8°).
      → `CAMERA_MODEL = "fisheye"`

      ⚠ **표기 사양 "2.8mm / D=148° / H=118°" 는 과장이었다.**
      실측은 **3.36mm / 대각 108.8°** 다. 예전에 여기 적혀 있던 "f_eff 2.604mm,
      f_px 755, 대각 138°" 는 그 표기에서 역산한 값이라 **29% 틀렸다.**
      저가 M12 렌즈는 표기 화각을 부풀리는 게 흔하다 — **다시 역산하지 말 것.**

      **⚠ `algorithm.md` 4장 시뮬레이션을 다시 돌려야 한다** — 화각이 예상보다
      좁아졌다(1m 높이에서 보이는 폭 2.88m → 1.99m). 물체가 프레임을 더 빨리
      벗어나 관측 구간이 짧아지므로 궤적 추정 정확도에 직접 영향이 있다.

- [x] **`CAMERA_FX/FY/CX/CY`** ★ — **2026-08-19 체커보드 캘리브레이션으로 확정.**
      `prep/calibrate.py capture` → `solve --camera gs`
      23장, RMS 재투영오차 **0.411 px**, 9/9 화면분할 커버, 기울임 포함.

      → `CAMERA_FX = 973.0`, `CAMERA_FY = 974.0`, `CAMERA_CX = 657.0`, `CAMERA_CY = 535.0`

      주점이 화면 중앙(728, 544)에서 **cx −71px** 벗어나 있다. 센서가 렌즈 광축에
      정확히 안 맞춰진 것이고 M12 나사 마운트에서 흔한 일이다.

      **독립 검증(줄자):** 벽에서 1.02m 떨어져 화면 가로 실폭 측정 → **2.20m**.
      캘리브레이션 예측 2.03m (+8%), 표기 역산 예측 2.94m (−25%).
      8%는 거리 기준점(입사동 vs 렌즈 앞면)과 가장자리 눈금 읽기 오차 범위이고,
      표기값은 74cm나 빗나가 측정 오차로 설명되지 않는다.

      ⚠ **초점을 다시 맞추면 이 값들은 무효다.** M12는 나사로 초점을 잡는 구조라
      실효 초점거리가 같이 바뀐다. **f가 10% 틀리면 깊이도 10% 틀어진다.**

- [x] **`CAMERA_DISTORTION`** ★ — 위 캘리브레이션에서 같이 나왔다.
      → `(-0.1432, 0.0282, -0.0445, 0.288)`
      **어안이므로 (k1,k2,k3,k4) 4개다** — 핀홀의 (k1,k2,p1,p2,k3) 5개와 개수도 의미도
      다르니 섞지 말 것.

      실측 계수로 θ_d/θ 를 계산하면 화면 안(최대 입사각 54.4°)에서 **0.96~0.99** —
      거의 등거리이고 cv2.fisheye 모델과 맞는다.
      ⚠ 다만 **화면 밖에서는 발산한다** (70°에서 2.13). 프레임 밖으로 외삽하면
      조용히 틀린 값이 나오므로 `fisheye.py`가 경고를 띄운다.

      > **⚠ 이 오차는 재투영 잔차로 못 잡는다.** 어안 좌표를 보정 없이 넣으면 착지 예측이
      > 입사각 62°에서 10cm, 80°에서 **158cm** 틀리는데 **잔차는 1.9~2.7px로 계속
      > `MAX_RESIDUAL_PX`(4.0) 아래**다. 잔차는 관측끼리의 일관성을 재지 투영 모델의
      > 정확성을 재지 않기 때문이다. 캘리브레이션으로 직접 확인하는 수밖에 없다.
- [ ] **`CAMERA_OFFSET_M` — 상수 자체가 없다** ★
      `trajectory.predict_landing`이 "카메라 = 로봇 회전 중심"을 전제하는데, 설계상

      장착 위치를 확정한 뒤 상수를 넣고 착지점에서 빼면 된다 (ω=0이라 단순 벡터 덧셈).
      ../docs/open-questions.md 참고.

- [ ] `YOLO_MODEL_PATH` — 학습·Hailo 변환 완료 후 `.hef` 경로

## 2. 값을 채워도 별도 연동 코드가 필요한 것

- [ ] **`vision.Camera`** — Picamera2 실제 캡처.
      `prep/camera.py`에 노출·게인·auto_lock·노이즈리덕션 처리가 이미 다 들어 있으므로
      재사용하는 게 맞다. 단 `prep/camera.py`의 `read()`는 `time.monotonic()`을 쓰는데,
      여기서는 **`SensorTimestamp`로 바꿔야 한다** — 파이썬이 버퍼를 받은 시각에는
      스케줄링 지터가 섞여 있고 궤적 피팅이 그걸 물체의 운동으로 읽는다
- [ ] `vision._HailoYolo` — HailoRT 실제 추론 (⚠ API는 실제 버전 문서로 검증 필요)
- [ ] `communication.SerialLink.__init__` — pyserial로 포트 여는 코드

## 3. 만들어야 하는 것

- [x] **`prep/calibrate.py`** — 만들었다. `capture`(체스보드 촬영, 3x3 커버리지 추적) +
      `solve`(계산 → JSON + config 스니펫) 두 서브커맨드.
      **모델이 pinhole이 아니라 fisheye로 바뀌었다** — 프로파일의 `calib_model`을 보고
      `cv2.calibrateCamera` / `cv2.fisheye.calibrate`를 자동으로 고른다.
      실측 f_px에서 **렌즈 mm를 역산해 출력**하므로 렌즈 각인을 못 읽어도 확정된다.
      체스보드 인쇄해서 15~20장 찍고 `solve --model fisheye` 하면 된다.
      **데이터 수집을 막지 않는다** — `capture_dataset.py`는 초점거리를 쓰지 않는다

## 5. prep/ — 동작 수정할 것 없음

`prep/`는 그대로 쓰면 된다. 확인한 내용:

- 라벨 형식 `cls cx cy w h` — bbox 중심을 적고 있으므로 그대로 유효.
  `w, h`도 계속 적는다 (궤적 추정엔 안 쓰지만 검출기 학습에는 필요)
- `CLASSES = ["trash"]` — 세 파일(capture/prepare/review) 통일 완료
- `edge` 기각은 유효하다 — 잘린 부분의 중심은 진짜 물체 중심이 아니기 때문
- `measure_sigma_w.py`는 합격 기준이 아니다. 정지 물체를 거리별로 찍을 필요 없이
  투척만 하면 된다

남은 것은 설명 주석뿐이다 (동작 무관, 급하지 않음):
- [ ] `capture_dataset.py` 23·29·102행, `review_labels.py` 6행 — "bbox 폭이 곧 거리"
      라는 옛 설명이 남아 있다. 나중에 한 번에 정리
