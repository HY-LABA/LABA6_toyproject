# 데이터 수집 (쓰레기 분류기 학습용)

던진 물체를 촬영해서 **자동으로 라벨링된 크롭 이미지**를 모으는 도구입니다.
사람이 이미지를 한 장씩 라벨링하지 않습니다.

## 원리 — 왜 손으로 라벨링하지 않아도 되는가

세 단계로 나뉩니다.

1. **블록 단위 선언** — "지금부터 10번은 전부 쓰레기만 던진다"고 명령줄에서 **한 번** 선언합니다.
2. **탄도 게이트** — 검출기가 찾은 궤적에 포물선을 피팅합니다. 던진 물체는 중력을 따라 포물선을 그리지만, **팔·그림자·지나가는 사람은 그리지 않습니다.** 잔차가 큰 트랙은 버려집니다.
3. **자동 상속** — 살아남은 트랙의 모든 크롭이 그 블록의 라벨을 그대로 물려받습니다.

즉 **라벨은 사람이, 위치는 물리가** 결정합니다. 소프트웨어는 "무엇이 쓰레기인지" 전혀 모릅니다 — 그건 지금 학습시키려는 대상이니까요. 소프트웨어는 "무엇이 날아가고 있는지"만 판단합니다.

포물선 게이트를 통과하지 못한 트랙은 버리지 않고 `distractor`로 저장합니다. 던지는 순간의 팔, 그림자, 검출기 오탐 — 분류기가 실제로 필요로 하는 네거티브 샘플이고, 공짜로 얻어집니다.

## 1. 설치

```bash
sudo apt install -y python3-opencv python3-numpy
```

- `picamera2`는 Raspberry Pi OS Bookworm에 기본 포함되어 있습니다.
- OpenCV는 **반드시 apt로** 설치하세요. pip는 ARM에서 소스 빌드를 시작해 한 시간 넘게 걸립니다.

## 2. 물리적 세팅

| 항목 | 값 |
|---|---|
| 카메라 높이 | 약 0.8 m |
| 카메라 각도 | 위쪽으로 약 16° (`--tilt -16`) |
| 던지는 위치 | 2 m, 3 m 지점에 바닥 표시 |
| 조명 | **자연광 또는 DC LED** |

### 조명이 가장 중요합니다

한국 상용 전원은 60 Hz라 형광등·LED가 **120 Hz로 맥동**합니다. 배경 차분은 이 밝기 변동을 "화면 전체가 움직였다"고 해석하므로, 깜빡이는 조명 아래에서는 검출이 전부 쓰레기값이 됩니다.

창가 자연광이나 DC 구동 작업등을 쓰세요. 이건 선택이 아니라 전제 조건입니다.

## 3. 실행 전 점검 (반드시 먼저)

### 3-1. 깜빡임 테스트 — 아무도 움직이지 않는 상태로

```bash
python3 tools/collect.py --check --max-frames 200
```

**검출이 0건**이어야 합니다. 정지된 장면에서 블롭이 잡히면 조명 깜빡임입니다. 여기서 통과하기 전에는 절대 다음으로 넘어가지 마세요.

### 3-2. 투척 테스트 — 3~4개 던져 보기

```bash
python3 tools/collect.py --check
```

세 가지를 확인합니다.

- 던질 때마다 `-> PROJECTILE`이 뜨고 잔차(residual)가 **6 px 미만**
- 요약의 `areas`가 `[300, 60000]` 안에 들어옴 (경계에 가까우면 경고가 출력됩니다)
- 물체가 있는 프레임에서 검출이 **1개** (0개도 5개도 아님)

통과하지 못할 때:

| 증상 | 조치 |
|---|---|
| `areas`가 상한에 근접 | `--max-area` 를 올리세요. 안 그러면 **가장 가까운 프레임들이 조용히 버려집니다** — 가장 크고 선명한, 학습에 제일 좋은 크롭들입니다 |
| `areas`가 하한에 근접 | `--min-area` 를 낮추거나 더 가까이서 던지세요 |
| `PROJECTILE`이 전혀 안 뜸 | 궤적이 화면 밖으로 나가고 있습니다. 피팅에는 포물선의 곡률이 필요하므로 **비행 전체가 화면 안에** 있어야 합니다. `--tilt`, 카메라 높이를 조정하세요 |

## 4. 실제 수집

**물체 하나당 명령 한 번**입니다.

```bash
python3 tools/collect.py --label trash --object-id can_coke_01 \
    --session s01 --block b01 --target 10
```

트랙이 하나 적립될 때마다 비프음이 납니다. 화면을 보고 있지 않아도 됩니다.

### 블록을 번갈아 가세요

**같은 세션(같은 장소·같은 조명·같은 오후) 안에서** 클래스를 교대합니다.

```
b01 쓰레기(10) → b02 비쓰레기(10) → b03 쓰레기(10) → b04 비쓰레기(10) → ...
```

> **월요일엔 주방에서 쓰레기만, 화요일엔 라운지에서 비쓰레기만** 찍으면 모델은 물체가 아니라 **방을 학습합니다.** 정확도 99%가 나오고 실전에서 완전히 실패합니다. 두 클래스의 배경·조명·시간대를 똑같이 유지하는 것이 유일한 방어책입니다.

### `--object-id`를 반드시 물체마다 다르게

같은 콜라캔을 10번 던졌다면 그건 **하나의 물체**입니다. 학습/평가를 나눌 때 물체 단위로 통째로 분리해야 하는데, `object_id`가 없으면 그게 불가능합니다. 이게 없으면 나중에 나오는 정확도 수치는 의미가 없습니다.

### 목표 수량

| 클래스 | 물체 종류 | 각 투척 |
|---|---|---|
| `trash` | 15~20종 (캔, PET병, 과자봉지, 구긴 종이, 종이팩) | 10회 |
| `not-trash` | 20~30종 (휴대폰, 열쇠, 책, 머그컵, 공, 리모컨) | 10회 |

**투척 횟수보다 물체 종류가 훨씬 중요합니다.** 크롭 13,000장이라도 한 번의 투척에서 나온 30장은 25 ms 간격의 거의 같은 사진이라, 실질적인 표본 수는 **투척 횟수(약 450)** 에 가깝습니다. 시간이 부족하면 `30종 × 7회`가 `15종 × 14회`보다 낫습니다.

## 5. 결과물

```
data/s01/
  crops/trash/…png        64×64 크롭
  crops/not-trash/…png
  crops/distractor/…png
  frames/…jpg             원본 프레임 전체
  manifest.jsonl          크롭 1장당 1줄
```

원본 프레임도 저장합니다. 나중에 검출기나 크롭 크기를 바꿀 때 **다시 던지는 게 아니라 다시 자르면 되도록** 하기 위함입니다.

`data/`는 `.gitignore`에 있으니 저장소에 올라가지 않습니다. 수집이 끝나면 따로 전달해 주세요.

## 6. 주요 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--label` | — | `trash` 또는 `not-trash` (필수) |
| `--object-id` | — | 물체 식별자 (필수) |
| `--session` / `--block` | `s01` / `b01` | 세션·블록 구분 |
| `--target` | 10 | 이 블록에서 모을 투척 수 |
| `--exposure` | 1000 | 노출 시간(µs). 블러를 줄이는 가장 중요한 값 |
| `--gain` | 4.0 | 노출을 늘리지 말고 이걸 올리세요 |
| `--min-area` / `--max-area` | 300 / 60000 | 블롭 면적 범위 (전체 해상도 기준) |
| `--tilt` | -16.0 | 카메라 각도(도). 음수가 위쪽 |
| `--source` | `picamera2` | `synthetic`으로 카메라 없이 동작 확인 가능 |

카메라 없이 파이프라인만 확인하려면:

```bash
python3 tools/collect.py --check --source synthetic
```

## 참고

`--fx`(초점거리) 기본값 1357은 **Camera Module v2.1을 1640×1232로 비닝**했을 때의 값입니다. 이 값이 조금 틀려도 **수집에는 지장이 없습니다** — 포물선 게이트는 6개 자유도로 피팅하므로 일관된 투영이면 잔차가 낮게 유지됩니다. 정확한 캘리브레이션은 실제 로봇 구동 단계에서 필요하고, 수집을 위해 미룰 이유는 없습니다.
